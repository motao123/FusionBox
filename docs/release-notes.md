# 版本说明（面向使用者）

> 本文件是 `fusionbox update` 升级完成后打印的"本次更新内容"，也是 CNB Release 的说明正文。
> 写作约定：只写使用者能感知到的变化与需要做的动作，用书面语；不写审计过程、判级、
> 扫描器结论、验证口径这类维护者内部信息——那些记在 [CHANGELOG.md](CHANGELOG.md)。
> 每个版本一节，节标题必须是 `## vX.Y.Z`（升级提示按版本号截取当前版本那一节）；
> 版本号与 `version.txt` 的一致性由 CI 的"Release version consistency"检查强制。

## v1.48.1

- **订正上一版说明里的一处不准确描述**：v1.48.0 的说明把「卸载时会报错」这个问题写成
  「卸载卡在中间、状态没写完整」，这与实际不符——卸载本身是正常完成的，容器已删除、数据与
  凭据按设计保留，真正的问题只是命令以报错结束，并且少打印一行「凭据保留在哪」。
  这个错误是我们自己复核时发现的，已按代码的实际行为改写。
- 本次**没有任何功能变化**，代码只改了一处注释。如果你已经升到 1.48.0，正常升级即可。

## v1.48.0

- **新增 2FAuth 条目**：自托管的双因素验证码管理器，TOTP / HOTP / Steam Guard 都能管，
  单容器 + SQLite，容器以普通用户（uid 1000）运行，只监听本机 `127.0.0.1:8098`。装好后
  打开页面注册账号就能用。
- **新增 Nexterm 条目**：自托管的 SSH / VNC / RDP / SFTP 远程管理面板，只监听本机
  `127.0.0.1:8099`。有两处需要如实说明：
  - 它以容器内 root 运行——该镜像没有声明数据卷，换成普通用户会在启动阶段因无法创建
    数据目录而直接失败（实机验证过）。能力收敛（全部 cap 丢弃 + 禁止提权）照常生效。
  - 它走桥接网络，所以官方推荐 host 网络才有的能力用不了：网络唤醒、连接宿主机本机
    端口上的服务；另外没有挂载 Docker socket，它内置的 Docker 管理功能也不可用。
- **凭据生成支持三种编码了**：上一版只会生成 URL 安全 base64，而 2FAuth 这类应用要求
  标准 base64，用错了它启动就失败（返回 500）。现在应用可以按需要声明 `urlsafe` /
  `base64` / `hex`。这个坑是实机试出来的，不是照文档写的。
- 两个新条目都跑通了完整生命周期：安装 → 健康检查通过 → 卸载保留数据与凭据 → 复用数据
  重装后**凭据指纹逐字节不变**。
- **修一个卸载时会报错的问题**：上一版新增的「卸载后打印凭据保留位置」，对一部分早期形态的
  应用会触发报错。卸载本身是正常完成的（容器已删除、数据与凭据按设计保留），但命令会以报错
  结束，并且少了「凭据保留在哪」这行提示。现在不会再报错。
  （这个问题是完整回归跑出来的，不是用户反馈。）

## v1.47.0

- **受管应用可以带「安装时生成的凭据」了**：像 LiteLLM 这类要求随机密钥的服务，现在安装
  时自动生成主密钥与数据库口令，写进 **0600 文件**后由 Compose 引用。密钥不进 compose
  文件、不进命令行、不进系统备份，只有宿主机上的保密文件和容器进程环境能看到。
- **新增 LiteLLM 条目**（模型网关 + PostgreSQL）：镜像摘要固定、依赖顺序启动，仅监听本机
  `127.0.0.1:8097`。装好后请用 `docker exec` 进入容器查看首次配置入口。
- **凭据不重复生成**：卸载会保留凭据，重装复用同一份——避免作废已经存进应用数据库的密钥
  （真机验证过重装后指纹逐字节不变）。
- **修复一个端口冲突**：`ntfy` 与 `rocketchat` 曾都用 8091，装了其中一个就装不了另一个；
  `ntfy` 让位到 8095。目录校验现在会直接拒绝两个条目共用同一端口，不再拖到安装时才报错。

## v1.45.0

- **新增「官方脚本安装」入口**：有些应用装不进本工具的受管模型（需要特权容器、
  Elasticsearch，或必须占用公网裸端口），对它们不再强行接入，而是提供一条直通上游
  官方安装脚本的路——`fusionbox market official install <id>`，也可在市场菜单里选。
  首批收录 **JumpServer**（堡垒机）与 **SafeLine 雷池**（WAF）。
- **执行前你会看到脚本指纹**：下载后先展示来源与 SHA256，并打印脚本地址，需输入 `YES`
  才执行。这类脚本会创建特权容器或改动系统，所以只在交互终端可用（脚本与 CI 中直接拒绝）。
- **这些应用装完后归上游管**：本工具不接管其升级、卸载与备份，请按上游官方文档操作。
- **下载更可靠了**：以往上游地址返回 404 时，错误页会被当成文件悄悄存下来（拿它当
  脚本执行不会有任何报错）；现在 HTTP 错误会直接判为失败并明确提示。

## v1.44.3

- **代理后端只剩 Xray / v2ray / sing-box**：Clash.Meta 已从安装菜单移除。它此前虽然能装上，
  但无法在本工具里添加节点，服务也起不来——它的配置格式与 FusionBox 生成的不同。
- **如果你之前装过 Clash.Meta，不用担心**：`fusionbox proxy uninstall` 仍会把它和它的服务
  一并清理干净。
- 不需要你做任何操作。Xray / v2ray / sing-box 的安装、节点管理、状态查询方式完全不变。

## v1.44.2

- **代理配置校验失败时真正回滚了**：上一版的"回滚"实际是把刚写入的坏配置原样写回，
  旧的好配置已经丢失。现在校验失败会恢复到你原来的配置，服务维持原状。
- **校验失败不再重启代理服务**：添加/删除节点时若新配置未通过内核校验，操作中止，
  坏配置不可能被加载进正在运行的代理。
- **报错信息正常显示了**：上一版三处提示因内部文案编号写错，界面上显示的是
  `MSG_PROXY_xxxx` 这样的编号而不是说明文字。
- **校验用的是当前内核**：上一版会用磁盘上找到的第一个内核去校验配置，机器上装过
  多个内核时可能用错内核、把合法配置误判为坏配置。
- **安装 Xray/v2ray 更稳**：解包所需的 unzip 缺失时会自动安装，且安装失败会先刷新
  软件包索引再重试一次（最小化系统上索引过期是常见原因）。

## v1.44.1

- **移除 MTProto 协议**（v1.43.11 引入）：实测发现 Xray 与 v2ray 的当前版本都已
  不支持 MTProto 入站（配置会被内核拒绝，且一个坏配置会拖垮该后端下的全部代理
  配置）。协议总数回到 15 种。
- **代理配置加内核校验**：添加/修改代理配置时会先用内核的 test 模式校验，失败
  自动回滚旧配置——坏配置不再可能影响正在运行的代理。
- **安装代理内核更省心**：Xray/v2ray 发行包解包所需的 unzip 缺失时会自动安装。

## v1.44.0

- **受管应用新增 RocketChat 团队聊天**：`fusionbox market managed install rocketchat --confirm`。
  MongoDB 双容器、镜像摘要固定、依赖顺序启动，仅监听 localhost:8091（公网访问请用
  `fusionbox web` 配反向代理 + TLS）。首次访问网页向导创建管理员。支持复用数据重装
  与按服务换镜像。
- **README 软件数与源码派生值对齐**：市场应用计数在主页与两份 README 之间不再有
  「下限口径」与「精确口径」的分歧，统一由源码派生并由闸门强制。

## v1.43.11

- **代理新增 MTProto 协议**：Telegram 专用代理。`fusionbox proxy add` 选择 MTProto
  （仅 Xray 后端支持；v2ray-core 已弃用该 inbound），生成配置后直接给出
  `tg://proxy?server=…&port=…&secret=…` 分享链接，在 Telegram 里点开即用。
  协议总数 15 → 16。
- **评测矩阵新增 UnixBench**：经典 UNIX 基准测试，编译 byte-unixbench 后运行
  CPU 与文件拷贝项，完整一轮约 30 分钟（重型档）。上游为 bench.sh 同作者的
  teddysun/across 仓库，已纳入上游 URL 存活巡检。
- **协议计数同步**：主页与 README 的协议总数已更新为 16 种。

## v1.43.10

- **新增内存压测**：`fusionbox system memtest [大小MB] [轮数]`，也可在
  `fusionbox system tools` 菜单选第 13 项。基于 memtester：默认取当前可用内存的
  一半（下限 64MB），硬上限为可用内存的 90%——宁可测得少，也不会把机器压到
  内存耗尽。memtester 未安装时交互确认自动安装；脚本/管道等非交互环境只打印
  安装提示，不会偷偷装包。压测发现错误会明确报警（建议更换内存或联系服务商）。
- **测试卫生**：修复更新路径的快捷链守卫——当部署目标不是标准安装位（如测试的
  临时目录）时不再写 `/usr/local/bin` 全局快捷链。这一直是测试环境软链泄漏的
  根源，也是此前 `fb: command not found` 悬空链问题的根因。

## v1.43.9

- **配置文件注释不再被写坏**：修复 `privacy` / `lang` 等写配置操作的一个格式缺陷——
  正则匹配会吞掉行尾注释前的对齐空格，导致每次写配置都把注释粘到值上
  （例如 `stats: false# 匿名使用统计…`）。现写入时注释统一保留两格缩进，
  已被粘住的注释会在下一次写配置时自动恢复正常对齐。功能行为不受影响，
  纯可读性修复。

## v1.43.8

- **重装/更新会自动修复失效的 `fb` / `FB` 快捷命令**：如果这两个命令是指向已不存在
  目标的悬空软链（例如某次安装的临时目录被清理后遗留），重装或更新时会自动重建；
  此前"外部同名命令不覆盖"的保护守卫会把这种断链误当成别人的命令而放任不管，
  导致 `fb` 永远 command not found。真正的外部同名命令（正常文件、有效的他人软链）
  仍然一律不碰。

## v1.43.7

- **第三方脚本源更可靠**：新增"上游 URL 存活巡检"——评测矩阵与工具类功能调用的第三方
  脚本地址（当前 21 个）全部纳入持续探活，任何一个失效都会让 CI 变红，而不是等用户
  踩到才发现。本轮基线实测 21/21 全部存活。
- **卸载更干净**：卸载后不再遗留空的主体目录。
- **文档更精确**：安装命令注明需要系统已带 curl 或 wget（否则命令会静默失败，这是
  此类安装命令的通病）；历史验收数据明确标注为"历史基线"，与当前口径分开。
- **质量口径**：补跑了完整回归套件并覆盖 v1.43.4-6 的全部改动，零失败；本轮还修正了
  一处变更日志违反项目外部引用策略的问题。

## v1.43.6

- **新增"系统一键重装"**：`fusionbox system tools` 菜单第 12 项。调用上游
  [bin456789/reinstall](https://github.com/bin456789/reinstall)（13k+ 星、GPL-3.0、持续维护），
  目标系统支持 Debian 12/13、Ubuntu 22.04/24.04、Alpine 3.22 与自定义 DD 镜像（https URL）。
  GitHub 不可达时自动改走 CNB 镜像下载上游脚本，执行前展示脚本 SHA256 指纹。
- **⚠ 使用前必读**：重装会**销毁整盘数据且不可回滚**。仅限 KVM/独立服务器（OpenVZ/LXC/
  容器不支持）；仅在交互终端可用（脚本/CI 自动拒绝）；需要连续确认三次（风险告知、
  输入 YES、最终确认）。新 root 密码可直接输入或由工具自动生成（只展示一次，请立即记录）。
  写入引导后需重启才真正开始重装；安装期间可通过商家 VNC 观察进度，安装失败也可
  SSH 救砖（上游自带 Alpine 救援路径）。
- **建议先备份**：重装前请确认已备份网站数据、数据库与配置文件；FusionBox 的
  `system backup` 只备份系统配置，不替代完整备份。

## v1.43.5

- **GitHub 访问受限也能更新**：`fusionbox update` 检查更新遇到 GitHub 不可达时，自动改走
  CNB 镜像下载发布资产——镜像资产与 GitHub 逐字节一致，仍通过 SHA256 校验后才安装；
  镜像与 GitHub 都不可用才回落 main 分支快照。与安装器共用同一套镜像
  （`FUSION_MIRROR` 环境变量可覆盖）。
- **生效时点请留意**：更新检查由你当前正在运行的版本执行。从 v1.43.4 或更早版本升级到
  本版时，那一次更新仍走原路径；**升到本版之后**，后续更新（含自动更新计划任务）才
  具备镜像后备能力。

## v1.43.4

- **GitHub 访问受限也能安装**：安装器检测到 GitHub 不可达时，会自动改走 CNB 镜像下载
  发布资产——镜像资产与 GitHub 逐字节一致，仍通过 SHA256 校验后才安装。
  纯镜像的手动安装步骤见 README「GitHub 访问受限时的备用安装」；自建镜像可用
  环境变量 `FUSION_MIRROR=https://你的镜像仓库` 指定。
- **依赖安装更抗抖动**：首次安装依赖若撞上软件源瞬时故障（如镜像池 404），安装器会
  自动刷新软件源索引并重试一次，不再直接中断。
- **语言一次性覆盖修复**：`FUSION_LANG=en fusionbox help` 这类单次覆盖，此前在任何
  已安装的系统上都会被配置文件里的 `lang: auto` 压掉（等于永远无效）。现在 `auto`
  表示"尚未选择"，环境变量可以生效；用 `fusionbox lang en` 显式设置过的语言仍然优先。
- **英文文档更纯粹**：README.en 的品牌名统一为官方英文名（宝塔 → BT Panel、
  哪吒监控 → Nezha monitoring、棉花云 → Mianhua Cloud），命令占位符改为英文
  （`<name>`、`<port>`、`<keyword>`、`<app>`），正文中文残留清零。
- **受限环境更安静**：HOME 不可写（例如容器内的受限用户）时，`fusionbox help` 等
  只读命令不再打印日志写入报错；日志自动停用，功能不受影响。
- **文档勘误**：README 曾写"完整 Docker 卸载尚未实现"，实际
  `fusionbox panels docker uninstall` 早已提供一键完整卸载（容器/镜像/卷/网络/软件包，
  数据可选保留，需输入 YES 确认），已按实际能力订正。
- **老用户建议补一个配置键**：v1.43.3 之前安装的用户，配置文件里没有
  `panels.bt_install_code`，`fusionbox panels bt` 会以不带渠道码的方式安装
  （与宝塔官方默认行为一致，不影响使用）。如需携带渠道码，在
  `~/.config/fusionbox/config.yaml` 的 `panels:` 段下加一行：
  `bt_install_code: rU2tN9mZ`。新装用户无需任何操作。

## v1.43.2

- **面板类一键部署默认只对本机开放**：Halo、KodExplorer、LinkStack、Uptime Kuma、
  Vaultwarden、Memos 部署完成后只监听 `127.0.0.1`，公网地址访问不到。要从外部使用，
  两种做法任选：用 `fusionbox web` 配反向代理并签发 HTTPS 证书后按域名访问；
  或临时用 SSH 隧道 `ssh -L 端口:127.0.0.1:端口 root@服务器` 在本地打开。
  其余一键部署（WordPress、Nextcloud、Discuz、Flarum 等站点类，以及 Emby、Jellyfin
  等局域网媒体服务）保持原来的对外方式，行为未变。
- **密码管理器不再接受陌生人注册**：Vaultwarden 部署后注册功能是关闭的。添加第一个账户时，
  按部署完成时屏幕给出的步骤临时打开注册、建号后再关闭。
- **监控栈模板不再有内置管理员口令**：使用 `templates/docker/monitoring.yml` 前，请在同目录
  的 `.env` 里设置 `GRAFANA_ADMIN_PASSWORD`；没设置时启动会直接报错提示，而不是用默认口令。
  Prometheus 与 Grafana 面板同样只对本机开放。
- **Web 模块生成的站点更规范**：新建站点、反向代理与 HTTPS 配置会带上三类常用安全响应头；
  已废弃的 `X-XSS-Protection` 不再下发。HSTS 需要你自行决定，配置里留有说明。
- **修复**：`fusionbox web` 里的"苹果 CMS 一键部署"此前一直用不上专用镜像，部署出来的是
  一个空的通用 PHP 容器；现在优先使用专用镜像，只有它不可用时才回落到通用方案。
- **遥测更收紧**（遥测默认关闭，需你主动开启才会上报）：上报请求的体积上限与跨域写入
  限制都已加强，统计接口的行为不变。
